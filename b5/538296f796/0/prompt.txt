## Problem

The contract gives every layer a `completion.criterion` but names no *bearer* for a deliverable's aggregate "Done when". A `kr-observed` milestone criterion with no node responsible for observing it means "all children closed" silently substitutes for "the KR moved" — the agentic-P4 hole (universal P1: observed is done). Same gap at story level: each sub-task verifies its own slice; nothing verifies the whole story end-to-end across the seams between sub-tasks.

## Change

Introduce an `acceptance` flag — a node-level boolean (`acceptance: true`) plus an inline task tag (`` `acceptance` ``), mirroring the existing `skeleton` flag exactly. An `acceptance` node/task verifies the **parent's** emergent / cross-seam criterion, and explicitly **never re-runs child criteria** (that is the redundancy guard). `skeleton` opens the end-to-end path; `acceptance` closes it.

## Grounding rule (reducibility-gated)

An `acceptance` node/task exists **only when the parent's "Done when" is irreducible to ∀child.done** — a KR moving, a journey crossing child seams, an integration no single child owns. When the criterion is just the sum of its children (many CRUD / theme milestones), there is no acceptance node — the milestone closing **is** the verification. This is the same reducibility test <issue id="200d4483-7d46-416f-b469-b79d64bfdd6c">ABA-283</issue> used to decide when `capability` is a node vs absorbed prose, reused on the completion axis instead of the structure axis.

## Linear mapping

Flag → **label** (orthogonal to structure, like `skeleton`). The `acceptance` issue closing **last** makes the milestone hitting 100% coincide with aggregate verification passing — no special field or tooling required.
